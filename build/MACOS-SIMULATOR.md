# Исправление подключения к симулятору на macOS

Если `sm-interpreter` в установленной IDE не имеет права на выполнение
(`-rw-r--r--`), симулятор не запускается и IDE показывает `CONN_ERR`.

1. Полностью закройте Cyberiada IDE через меню приложения → «Завершить» или `⌘Q`.
2. Скопируйте приложение из DMG в папку «Программы», если оно ещё не установлено.
3. Сохраните файл [fix-macos-simulator.command](fix-macos-simulator.command)
   в папку «Загрузки» на компьютере пользователя.
4. Откройте Терминал через поиск Spotlight: нажмите `⌘Пробел`, введите «Терминал»
   и нажмите Enter.
5. Вставьте следующую команду и нажмите Enter:

   ```bash
   bash ~/Downloads/fix-macos-simulator.command
   ```

   Если файл сохранён в другую папку, введите `bash ` с пробелом в конце,
   перетащите скачанный скрипт в окно Терминала и нажмите Enter.

6. В появившемся окне выберите установленную Cyberiada IDE из папки «Программы».
   Приложение также может называться `Lapki IDE.app`. Не выбирайте копию внутри
   открытого DMG.
7. Если Терминал запросит пароль администратора, введите его и нажмите Enter.
   Символы пароля при вводе не отображаются — это нормально.
8. После сообщения «Право на выполнение восстановлено» запустите IDE и проверьте
   подключение к симулятору.

Можно сразу указать путь к приложению:

```bash
bash ~/Downloads/fix-macos-simulator.command "/Applications/Cyberiada IDE.app"
```

Используйте фактическое имя приложения: оно также может называться `Lapki IDE.app`.
Скрипт совместим с системным Bash в macOS 10.15.7. Он добавляет право на выполнение
только файлу интерпретатора. Если файл принадлежит другому пользователю, `sudo`
запросит пароль администратора. Скрипт не изменяет настройки IDE и не снимает
карантин macOS. Если интерпретатора нет, скрипт сообщает об этом: нужно повторно
скопировать приложение из DMG с заменой.

Если право на выполнение уже есть, причина `CONN_ERR` требует отдельной диагностики.
Если после исправления ошибка осталась или скрипт завершился с ошибкой,
скопируйте полный вывод Терминала и передайте его разработчикам.
Проекты и настройки IDE при выполнении скрипта сохраняются.

## Предотвращение в новых сборках

В Git `resources/modules/darwin/sm-interpreter` должен иметь режим `100755`.
Дополнительно `build/after-pack.js` проверяет наличие `sm-interpreter` и
`lapki-flasher` в готовом `.app` и назначает обоим режим `755` до подписи и
создания DMG. Проверка действует и для объединённого universal-пакета.
Если обязательный модуль отсутствует, сборка завершается ошибкой.

Проверка упаковки и скрипта исправления без сборки DMG:

```bash
node --test build/test-macos-packaging.cjs
```

Эти проверки используют временные файлы. Для скрипта имитируются определение
macOS и выбор приложения; реальный запуск интерпретатора на Catalina и проверку
готового DMG нужно выполнять на Mac.
